# Веб-сервис обработки студенческих работ

Учебный Django-проект для передачи студенческих работ преподавателям, отслеживания статуса проверки и получения комментариев.

## Назначение

Сервис закрывает полный цикл обработки учебных материалов:

1. Студент регистрируется и входит в систему.
2. Загружает работу (PDF или DOCX).
3. Преподаватель просматривает файл, меняет статус и оставляет комментарий.
4. Студент видит результат проверки в личном кабинете.

Автоматическая оценка, проверка на плагиат и искусственный интеллект не входят в проект.

## Технологии

- Python 3.12+ (проверено на Python 3.13)
- Django 5.2
- SQLite
- HTML5, CSS3, Bootstrap 5
- стандартная сессионная аутентификация Django
- Django Forms и Django TestCase

## Установка и запуск (Windows PowerShell)

Откройте PowerShell в каталоге проекта.

### 1. Виртуальное окружение

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

Если выполнение скриптов запрещено, один раз выполните:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 2. Зависимости

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Миграции

```powershell
python manage.py migrate
```

### 4. Администратор

```powershell
python manage.py createsuperuser
```

Укажите логин, email и пароль. Суперпользователь автоматически получает роль администратора.

### 5. Запуск сервера

```powershell
python manage.py runserver
```

Локальный адрес: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

Панель администратора: [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/)

### 6. Тесты

```powershell
python manage.py test
```

## Как создать преподавателя

Открытая регистрация всегда создаёт студента. Роль преподавателя назначает только администратор.

1. Зарегистрируйте обычного пользователя через `/register/` либо создайте его в `/admin/`.
2. Войдите как администратор в [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/).
3. Откройте раздел «Пользователи».
4. Выберите нужного пользователя.
5. В поле «Роль» укажите «Преподаватель» и сохраните.

После этого пользователь входит через `/login/` и попадает в раздел поступивших работ.

## Демонстрация основных сценариев

1. Откройте главную страницу и зарегистрируйте студента.
2. В кабинете нажмите «Загрузить работу», укажите название и приложите PDF или DOCX.
3. Откройте созданную работу и убедитесь, что статус — «На проверке».
4. Выйдите и войдите преподавателем.
5. В `/teacher/works/` откройте работу, скачайте файл, выберите результат проверки и оставьте комментарий.
6. Снова войдите студентом и посмотрите обновлённый статус и комментарий в кабинете.
7. Убедитесь, что студент не видит чужие работы и не может изменить статус проверки.

## Ограничения загрузки файлов

Разрешены только `.pdf` и `.docx`. Максимальный размер задаётся параметром `MAX_UPLOAD_SIZE` в `config/settings.py` (по умолчанию 10 МБ). Измените это значение в одном месте, если нужен другой лимит.

## Публикация

- **GitHub Pages** — статическая витрина: <https://gloryspb.github.io/stud-works/>
- **Render** — рабочий Django-сервис (gunicorn). После первого деплоя адрес будет вида `https://stud-works-gloryspb.onrender.com`

GitHub Actions (`.github/workflows/ci-cd.yml`):

1. **CI** — `manage.py check` и тесты.
2. **CD Pages** — публикация каталога `pages/` на GitHub Pages.
3. **CD Render** — вызов Deploy Hook, если в секретах репозитория задан `RENDER_DEPLOY_HOOK`.

### Render

1. Войдите на [render.com](https://render.com) и подключите репозиторий `gloryspb/stud-works`.
2. Создайте Web Service (Python) или примените Blueprint из `render.yaml`.
3. Build: `pip install -r requirements.txt && python manage.py collectstatic --noinput`
4. Start: `python manage.py migrate --noinput && gunicorn config.wsgi:application --bind 0.0.0.0:$PORT`
5. В Settings сервиса скопируйте Deploy Hook и сохраните его в GitHub: `Settings → Secrets and variables → Actions → RENDER_DEPLOY_HOOK`.
6. При необходимости задайте переменную репозитория `RENDER_URL` (точный URL сервиса) — она подставится в витрину Pages.

На бесплатном плане диск эфемерный: SQLite и загруженные файлы могут пропадать после перезапуска.

### GitHub Pages

В репозитории: `Settings → Pages → Source: GitHub Actions`. После пуша в `main` workflow сам опубликует сайт.

## Безопасность (учебный контур)

- пароли хранятся только в виде хэшей Django;
- формы защищены CSRF;
- доступ к кабинетам, файлам и проверке контролируется на сервере;
- файлы не отдаются по прямым публичным ссылкам, а только через представление с проверкой прав;
- каталог `media/`, база SQLite и виртуальное окружение исключены из Git.
